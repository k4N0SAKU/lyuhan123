> 时长：3~5 分钟 ｜ 结构：痛点 → 架构 → 演示 → 指标 → 创新点
> 交付：交团队录制；本文件含逐镜头脚本、口播文案、素材清单与核对项。
> 数字口径：全部取自 `docs/data_dict.json`（录制前跑
> `python scripts/check_docs_consistency.py` 确认全绿再开拍）。

- [ ] 预热：先跑 1 轮完整演示（管线加载 ~90s 不入片）

- [ ] 备用素材：`benchmarks/results/p6_full_bench.json`（指标页截图源）、
      `attack_verdicts.json`（安全页）、p6_tables.md（创新点页）

      10 轮稳定性证据以 `p7_demo_stability.json` 截图呈现）
- [ ] 字幕/口播稿按下方文案；金额/数字播读前对照 data_dict

## 分镜脚本

### 镜头 1｜痛点（0:00–0:40，约 40s）
**画面**：静态图或简单动画——左侧"明文直传"示意（手机→大模型 API，红色
泄露标记），右侧法规关键词条（个保法/等保/数据不出域）。
**口播**：
> 政务热线、企业工单正在大规模接入大模型，但市民的姓名、证件号、投诉
> 原文一旦明文进入模型 API，就等于把隐私交给了第三方；而《个人信息
> 保护法》与等级保护要求数据不出域。传统 MPC、FHE 框架又普遍没有国密
> 合法性、部署重、开销失控。我们要回答的问题是：**隐私数据可用不可见，
> 推理还能真的跑起来吗？**

### 镜头 2｜架构（0:40–1:30，约 50s）
**画面**：`docs/01` 第 2 章拓扑图（P0/P1/P2 三节点+端口 17401~17403）；
逐条亮起：SM2 双向认证 → SM2DH 会话 → SM4-GCM 通道 → 密文推理 → 白名单解密。
**口播**：
> 方案是三参与方结构：P0 数据属主本地加密，P1 密钥服务做认证中枢与
> 密钥全生命周期，P2 持密文做推理。控制面全链国密——SM2 双向认证、
> SM3 哈希链审计、SM4-GCM 通道（RFC 8998 标准向量锚定）；数据面用 CKKS
> 同态与秘密分享混合的模式 B：密文线性层 + 分享域非线性，每次转换都带
> 一次一密掩码，**P0 的解密只放行两类白名单值**——掩码转换值和最终结果。

### 镜头 3｜演示（1:30–3:10，约 100s）
**画面**：演示页面实录（浏览器全屏）。
分步：
1. （10s）输入区：切"政务咨询"场景，展示模拟姓名/证件号**角标**
   → 口播："全模拟数据——"
2. （10s）点"开始演示"→ 拓扑面板亮起"认证中 → 会话建立"
   → 口播："三条链路双向证书认证 + SM2DH 密钥协商，全程 SM4-GCM"
3. （30s）状态进入"密文推理中"，指标条跳动（分段时延/流量/内存）
   → 口播："密文参与推理：CKKS 线性层、MPC 非线性，明文只在 P0 内存——
   绿灯每轮扫描 P1/P2 视图为零命中。"
4. （20s）"结果解密（白名单）"→ 轮次表出标签+业务映射
   → 口播："结果回 P0 白名单解密，业务语义映射示例"
5. （15s）"销毁+审计核验 → 完成"，banner 显示审计链通过
   → 口播："会话密钥两遍覆写销毁，审计哈希链核验通过。"
6. （15s）快速点一下"模式 A"标签展示如实不可用面板
   → 口播："全密文模式 A 因本栈参数上限如实标注不可用——不模拟、不冒充。"
**加速处理**：推理等待段 4× 快进（角标"加速 4×"），不改数字。

### 镜头 4｜指标（3:10–4:00，约 50s）
**画面**：`p6_tables.md` 表格 + data_dict 数字（大字标注 JSON 出处）。
**口播**（数字均标注来源）：
> 四项资源指标全部脚本自动采集、20 轮 P50/P95：代码 9,949 行；
> 密文推理 4/8/12 层分别 121.7 / 237.7 / 371.8 秒（回环 CPU）；
> 节点内存峰值 max 15.7 GiB（演示机按此选型）；流量逐通道计数含协议头。
> 与明文基线 23.6ms 的数量级差异我们不回避——瓶颈与优化路径写在对比报告里。
> 安全侧：五类攻击 30 项自动化判定，28 防御成功、2 项为**预先声明的
> t=2 边界演示**、0 失败。

### 镜头 5｜创新点（4:00–4:40，约 40s）
**画面**：05 报告的两张 A/B 表。
**口播**：
> 两个实测创新点：第一，量化参数自适应——conv_fp16+emb_q22 组合在
> **一致率 1.000 不降**下把模型体积从 474.7 MiB 压到 312.7 MiB（-34.1%）；
> 同时诚实给出两个选择器失效的负结果。第二，线性层双实现 A/B——
> row-sum 对照实测比对角线+BSGS 慢 5.39 倍，用数据推翻了此前的排序推测。

### 镜头 6｜收尾（4:40–5:00，约 20s）
**画面**：复现命令 + 七份文档封面拼图 + GitHub 地址。
**口播**：

> 七份文档、攻击判定、基准数据全部可回读到 JSON。数据可用不可见，
