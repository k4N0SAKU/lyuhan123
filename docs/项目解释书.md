## 一、总体方案：三方架构与信任边界

题面六项要求（多方密文推理 / 认证与完整性 / 五类攻击 / 四项资源指标 / 抗 t 方合谋 / 痛点+对比+复现+创新）的落点总表见 `docs/00 §2`，这里只讲结构。

**参与方与信任边界的核心约束**：

- **CKKS 私钥只在 P0**（CKKS 是什么见 §二），且 P0 的解密被约束在**白名单**内：只有两处合法解密触点——①域转换掩码值（且值域受限）、②最终输出；
- **P1/P2 不持任何 CKKS 私钥材料**，各自只见密文与随机份额（"份额"= 秘密分享后的碎片，§二详解）；
- 安全声明口径为**半诚实参与方 + 恶意网络**。"半诚实"（semi-honest，也叫 honest-but-curious）= 敌手会忠执行程、但试图从看到的数据里捞信息——这是 MPC 文献的标准敌手分级，比"恶意"（malicious，可任意偏离协议）弱一档；
- 合谋门限 **t=1 精确到门限**：P1 或 P2 任一方单独被腐化，输入与中间状态保密；P1+P2 合谋即失守——这是当前构造的数学边界，预先声明并自动化演示（§五 P5）。

**为什么 t=1 是天花板**：秘密分享语义下，计算方所持份额之和恰为中间值；只有两个计算方的结构里，两方联合必然重构一切。要把门限提到 2，需要把 P0 纳入计算环（client-aided，即客户端辅助计算的 3-of-3 分享结构）或引入第四方（3-of-4 Shamir 分享）——已在 `docs/02 §3.3` 登记为升级路径，不在当前版本实现。

**两条运行模式**：

- **模式 B（主线）**：CKKS 密文跑线性层 + MPC 跑非线性层，中间靠 D5 域转换协议切换形态。演示与全部评测采用。
- **模式 A（纯秘密分享全 MPC）**：题面路线提示之一。受本栈 CKKS 参数上限阻断（§二），理论设计保留、不可实例化——如实申报；攻击测试对两模式分别执行，不混淆口径。

## 二、准备知识：三样密码工具（首次详解）

### 2.1 同态加密与 CKKS

**同态加密**（Homomorphic Encryption，缩写 **HE**）：允许直接对**密文**做运算、解密后结果等于对明文做同样运算的加密方案。普通加密是"死"的——动密文就解不开了；同态加密的密文是"活"的。

**CKKS** 是一种具体的同态加密方案（Cheon-Kim-Kim-Song 四位作者首字母，2017 年提出）：把**实数向量**编码进多项式环，支持近似加法与近似乘法——运算会引入微小噪声，但控制在精度预算内。它天生适合神经网络的**线性层**（矩阵乘法=大量乘加）。我们的实现栈：

- **SEAL**：微软开源的同态加密库（CKKS/BFV 方案的工业级实现）；
- **TenSEAL**：基于 SEAL 的 Python/C++ 封装库（面向机器学习场景），版本 0.3.14——注意它的高层接口**没有暴露旋转 API**，我们被迫直接调用底层 sealapi（§五 P2）；
- **OpenFHE**：后继一代的开源同态库（支持门限同态），是我们申报"模式 A/更大参数需换后端"时的目标库；
- **gmssl**：开源国密算法 Python 库（SM2/SM3/SM4），注意它**没有 GCM 模式**（§五 P2 自研的原因）。

几个必须懂的 CKKS 概念（后面反复出现）：

- **scale（缩放因子）**：CKKS 编码实数时乘的放大系数，乘法后 scale 会相乘变大，需要 **rescale**（重缩放）操作把它降回来；rescale 用的素数不是精确 2^k，每次会带来 1 ulp 量级的漂移（**ulp** = floating point 的最小精度单位，unit in the last place）；
- **N（环维度）**：多项式环 Z_p[X]/(X^N+1) 的维度，决定密文容量（约 N/2 个实数槽）与安全等级。**SEAL 强制 128 位安全等级的标准参数合规（TC128 约束，HEorg 标准参数集）**，实测 N=1024/2048 全被拒绝，N=4096 + 素数链 [30,30,40]（三个素数模数的位宽）可用。本栈上限 **N=2^15=16384**（n≥2^16 一律拒绝）；
- **噪声**：每次同态运算累加的误差。实测：2 层 3.8e-9 / 14 层 7.1e-9（@2^40 scale）——**CKKS 噪声是绝对量不是相对量**，所以回归指标用绝对 RMSE（均方根误差），且 `invariant_noise_budget`（噪声预算查询）不支持 CKKS，改用 decrypt_error_rmse（解密误差 RMSE）。

### 2.2 加性秘密分享与 MPC

**MPC**（Secure Multi-Party Computation，安全多方计算）：多方各持秘密输入，协作算出结果但互相不知道对方输入的密码学技术总称。

**加性秘密分享**：把数 x 拆成 r 与 x−r 两份（模 2^k 的环上加法，**Z_{2^k}** = 模 2^k 的整数环）。单独看每份都是均匀随机数，拼起来才是真值。我们的 D5 协议就是"CKKS 形态 ↔ 分享形态"的转换器。

**乘法问题与 Beaver 三元组**：两份份额相乘会冒出交叉项。解法：离线预生成随机三元组 (a, b, c=a·b)——**Beaver 三元组**（以提出者 Donald Beaver 命名），在线乘法时用它吸收交叉项，两方只需交换一次掩盖后的中间值。我们的三元组由离线生成器批量生产（`src/nodes/offline_triple_gen.py`）。

**敌手模型与门限**：

- **半诚实 vs 恶意**：如 §一所述，半诚实=只偷看不捣乱；恶意=可任意偏离协议（需要额外的验证机制）；
- **诚实多数 vs 不诚实多数（dishonest majority）**：诚实多数=被腐化方不足一半（如 3-of-4）；SPDZ 族协议可在不诚实多数下工作（容忍至多 n−1 方，但只能"带中止"——敌手可让协议失败但学不到东西）；
- **OT**（Oblivious Transfer，不经意传输）：MPC 基础原语——发送方发两条消息，接收方只能取其一且发送方不知其选择。2PC 框架 Cheetah 的核心组件之一就是 Ferret OT。

### 2.3 国密算法族

| 算法/标准 | 全称与用途 |
|---|---|
| **SM2** | 国家商用椭圆曲线公钥密码算法：数字签名、密钥交换、公钥加密。**SM2DH** = 基于 SM2 的 Diffie-Hellman 密钥交换协议，国标编号 **GB/T 32918.3**（第 3 部分：密钥交换） |
| **SM3** | 国家商用密码杂凑算法（输出 256 位摘要）——我们用它做审计链的逐条指纹 |
| **SM4** | 国家商用分组密码（128 位分组/密钥）——通道加密的底层算法 |
| **GCM**（Galois/Counter Mode） | SM4 的认证加密工作模式：计数器模式加密 + **GHASH**（Galois 域上的乘法哈希）生成认证标签，加密与防篡改二合一。规范为美国 NIST SP 800-38D；GCM 内部有计数器起点 **J0** 与初始加密块 **ICB**（initial counter block）——我们踩的坑就在这里（§五 P2） |
| **RFC 8998** | 把国密套件（SM2/SM3/SM4-GCM）引入 TLS 1.3 的互联网规范文档，其**附录 A.1 含官方标准测试向量**（固定输入→固定输出的参考实现结果），我们用它锚定 GCM 实现正确性 |
| **X.509 v3** | 公钥证书的格式国际标准（现行第 3 版，含扩展字段）——我们的证书体系按此结构构造（演示级） |

## 三、数据面设计

### 3.1 定点化（一切的前提）

CKKS 只能算定点数（小数点位置固定的整数表示）。方案：**Q16**（激活值：16 位小数位的定点记法，即数值放大 2^16 取整存储）、**Q22**（GPT-2 权重：22 位小数位）、**INT8**（BERT 权重：8 位整数）。实测**定点化后与浮点模型预测一致率 100%**（`quantize_eval_*.json`）。这一步必须最先钉死——后面所有密文计算的精度都建立在它的误差预算上。反面教材：INT8/FP16 混用权重使一致率跌到 0.89/0.944（§七 C2 的负结果之一）。

另一个必须知道的性质：**贪心解码对近并列 logit 敏感**（logit=模型输出的未归一化分类得分；两个得分差 ~1e-5 时 token 选择即翻转），所以生成口径的"一致"定义要按 token 级一致率（**token**=分词后的最小文本单位）。

### 3.2 CKKS 线性层

- **打包**：权重按**对角线方法**编码进明文多项式（矩阵第 i 条对角线对应一次旋转+乘加），密文向量 × 明文矩阵化为一系列密文旋转 + 明文乘加；
- **旋转优化**：**BSGS**（baby-step giant-step，大步小步法）：把 d 次旋转分解为 √d 次小步预旋转 + √d 次大步组合，旋转次数从 O(d) 降到 O(√d)；
- **实测成本**：768×768 单线性层约 4.2~4.5s（CPU，L=2 回环口径——L=2 是 P6 基准的管线截断标签，详见 docs/04 §2）——这是全系统时延的主导项之一；
- 两个实现级陷阱备忘：scale=1.0 明文编码会静默全零；rescale 后 scale 有 ulp 漂移，需 `_align_scale` 对齐。

### 3.3 域转换协议 D5（本方案的核心构造）

线性层输出是 CKKS 密文，非线性层要加性秘密分享——D5 负责两态切换，四步：

1. **入口**：P2 在密文域同态加随机掩码 `Enc(r)`。掩码按**目标层的精确 scale** 编码——rescale 素数非精确 2^k 会引起 scale 相对漂移，若掩码 scale 与密文 scale 不严格一致，relabeling 加法在 OTP 大值域下误差达 ±2¹²。**OTP**（One-Time Pad，一次性填充）：用与明文等长的均匀随机数遮蔽，信息论安全（无条件安全，与算力无关）。**掩码值统一 ≤2^20**，原因：掩码量级越大，ulp 抖动与编码残差线性放大（实测 2^37 时 δ≤5）；
2. **白名单①掩码解密**：P0 解出 y₁ = x+r——带 OTP 掩码，P0 仍不知 x（r 仅 P2 知）。y₁ 分发：P1 收 y₁，P2 自留 −r。这一步把"CKKS 形态"翻译成了"加性分享形态"；
3. **MPC 非线性**：两方在分享域上以 **minimax 多项式近似 + Beaver 三元组在线乘法** 计算 GELU/Softmax。**minimax**=最大误差最小化的多项式逼近准则，系数用 **Remez 交换算法**生成（数值逼近的经典算法）；**GELU**（Gaussian Error Linear Unit）与 **Softmax**（归一化指数）是 Transformer 的两个核心非线性函数；
4. **出口（RECRYPT）**：P1 取新掩码 s，P2 同态合成**新鲜密文**（fresh = 刚加密、噪声预算充足）`Enc(v) = Enc(w) − Enc(s)`，回到 CKKS 域进下一层。**不变量**：线性段输入必须是转换出口的 **fresh 双拷贝**（两份内容相同、各自独立加密的密文，分别供 QKV 与 FFN 使用）——P3 阶段一个结构性 bug 就是在这里破坏了布局（§五 P3）。

**成本结构**：每层 Transformer 触发 **10n 次域转换**（n 为词元数），转换主导通信（GB 级/请求的预算，`docs/01 §7.5`）。这就是"密文推理分钟级"的主要来源之一。

**掩码窗口**：`conversion.py` 的 `ConversionPolicy` 用三道值域护栏约束掩码行为——掩码值域 2^24、入口窗 [0, 2^49)、出口窗 [2^25, 2^36+2^24)。这些区间是精度墙推导出的安全工作域，模拟器论证按此给出口径（§五 P5）。

**白名单的设计意图**：P0 是唯一私钥持有方，攻击面在"P0 侧实现被滥用"；白名单把解密收口到两类值且掩码值域受限，消除了"随手解中间激活"的路径。这是 P1-R1 评审对 D5 的关键修订（原设计把门限密钥生成写进去，TenSEAL 无实现载体，评审后改为 P0 单钥+白名单——决策记录在 `docs/01 §8.4`）。

### 3.4 非线性算子：MPC 实现

GELU/Softmax 无法直接同态计算，用 **minimax 多项式近似**（P2 用 Remez 算法生成系数：GELU deg15 误差 5.067e-3、exp 单侧域 deg9 误差 6.8e-5，deg=多项式次数）+ **Beaver 三元组在线乘法**在秘密分享域完成。**Transformer 结构**速览：每层 = 自注意力（QKV = Query/Key/Value 三组线性变换）+ **FFN**（Feed-Forward Network，前馈网络）+ 残差连接 + **LayerNorm**（层归一化）；BERT 分类用 **[CLS]**（句首分类词元）的表示经 **pooler**（池化层）输出 **logits**。

### 3.5 控制面：全链国密

| 组件 | 构造 | 关键点 |
|---|---|---|
| 身份认证 | 离线 CA 签发 X.509v3 结构化证书 + SM2 挑战响应双向认证（一方发随机挑战、另一方用私钥签名应答，防重放需时间戳/随机数） | 演示级证书体系（生产需换 GM 证书链，已申报） |
| 密钥协商 | SM2DH 会话密钥（GB/T 32918.3） | 会话密钥由 node_id 规范标签 d0/d1 派生——曾因用本地 send/recv 命名派生导致两端密钥不一致（§五 P4） |
| 安全通道 | SM4-GCM 认证加密，自实现（gmssl 无 GCM） | **RFC 8998 附录 A.1 外部标准向量锚定**（§五 P2 教训） |
| 密钥轮换 | ratchet（棘轮，密钥按规则单向演进、旧密钥不回来）+ KEY_ROTATE 消息 | 单帧密钥泄露不回溯污染 |

| 销毁 | 密钥状态机 + 两遍覆写零化（内存写零两遍，不是"删变量"） | 注册→轮换→销毁全链生命周期测试覆盖 |

## 四、工程纪律：为什么每个数字可信

后续维护（尤其写报告书引用数字时）必须知道的三条铁律：

1. **D8 纪律**：性能数字只允许由 benchmark 脚本写入 `benchmarks/results/`（UTC 时间戳 JSON）；文档引用与 JSON 保持一致，杜绝手填。历史上手改文档数值引入过错值（如把 452.7 写进文档而 JSON 实测 474.7），由此建立了黑名单机制；

### P2 密码原语层（09-26）

**目标**：五件套原语全部落地并用实测校准理论参数。

**具体实现**：

1. **`src/crypto/ckks_ops.py`**：TenSEAL 高层没有旋转 API → 直接走 sealapi 自封装（加密/解密/明文乘/密文乘/显式 rescale/旋转）；确认 rotate_vector(+k)=左移语义；参数扫描：N=1024/2048 全被 SEAL 的 TC128 安全检查拒绝，N=4096+[30,30,40] 可用；噪声实测：2 层 3.8e-9 / 14 层 7.1e-9（@2^40 scale）。
2. **实现级陷阱清单**（全部实测确认，写进踩坑索引）：scale=1.0 明文编码静默全零；Ciphertext 无拷贝构造（用文件克隆绕过）；`Modulus(40)` 是值 40 不是 40-bit 素数（必须 `CoeffModulus.Create` 生成真素数链）；BSGS giant 组明文需预旋转 +j·baby；rotate 噪声 ~1e-6 大于乘法噪声；**rotate/multiply 单次耗时比 ρ≈1.7**——这个实测值后来成为 C3 选型模型的输入。
3. **`secret_sharing.py` + `beaver.py`**：模 2^k 加性分享、离线三元组生成器。
4. **`gm_cipher.py`：SM4-GCM 自实现**（gmssl 只有 SM4 单块加密原语，`padding_mode=None` 拿到底层自己拼 GCM）：GHASH 表驱动实现（16×256 预计算表按字节位置线性分解）8× 提速；`_ghash` 不能用 CRC 式反馈公式（那是错的——GHASH 是 Galois 域乘法，不是移位寄存器）。
5. **`threshold.py`**：门限解密模拟（模式 A 理论口径用）。
6. **minimax Remez 系数生成器**：GELU deg15 误差 5.067e-3、exp 单侧域 deg9 6.8e-5、inv 7 轮迭代、invsqrt deg4→3 轮（评审 B1 要求补做——P1 的理论误差界被实测校准推翻重算）。
7. **单元测试**：131 项 pytest（Python 测试框架）全绿（精度回归/均匀性/向量测试断言）。

**P2-R1：GCM 计数器偏移（本项目最重要的密码学教训）**：评审方独立交叉实现，实证我方密钥流偏移一格——`_gctr(key, J0+1)` 先自增风格 + 调用方再 +1 = 密钥流从 E(J0+2) 起（第二个计数器块开始加密），违反 NIST SP 800-38D 规定的"首块=E(K, J0+1)"。**为什么所有自测都没发现**：自洽往返（自己加密自己解）、篡改检测、GF(2^128) 代数测试，对"系统性错一格"的实现全部通过——错误实现与自己一致。修复：两处改传 J0，`_gctr` docstring 写明 ICB 语义，**RFC 8998 附录 A.1 标准测试向量 + 单零块断言入库**。纪律升格：**密码组合层必须锚定外部标准向量**——自洽测试对"实现与实现一致"的系统性错误无能为力。

**出口**：R1 闭环（GCM 修复经标准向量复核）。

### P4 认证与密钥全生命周期（09-27）

**目标**：控制面全量落地（认证/会话/轮换/审计/销毁）+ D5 从玩具直连升级为真实路径。

**具体实现**：

1. **`src/protocol/` 六件**：`messages.py`（19 类消息）、`auth.py`（X.509v3 证书 + SM2 挑战响应双向认证）、`session.py`（SM2DH 会话密钥 + SecureChannel 的 SM4-GCM 帧 + ratchet）、`keylifecycle.py`（注册表 + 状态机 + 两遍覆写销毁）、`audit_log.py`（SM3 哈希链 append-only）、`conversion.py`（D5 真实路径 + ConversionPolicy 掩码窗口，§3.3）。
2. **`src/nodes/`**：`base/links`（节点基类与连接器，LoopbackLink=进程内回环连接）、`provision`（CA 签发与分发）、`client/keynode/infernode`（三个角色的节点封装）、orchestrator（编排器，负责组网与生命周期）。
3. **握手与通道的关键坑**（都是实测踩出来的）：
   - **证书先行**——否则顺序死锁（响应者等证书、发起者等响应）；
   - transcript 链（握手过程的逐条记录）必须**收发双侧等价更新**，漏一侧则 KEY_ROTATE 后双端失配；
   - 通道密钥 KDF 盐（KDF=Key Derivation Function 密钥派生函数；盐=派生时混入的区分字符串）必须用 **node_id 规范标签 d0/d1**——最初用本地 send/recv 命名派生，两端各自算出不同密钥，是极隐蔽的逻辑 bug；
   - ratchet 语义：FIFO（先进先出）下 seq 先拒重放、滑动窗口兜底非 FIFO；轮换阈值 N 实际每 N+1 条触发一轮（触发帧自身计数）；KEY_ROTATE 的 transcript 基准 = 本帧之前的链值；
   - gmssl `sm2_generate_keypair` 返回 (pub, priv) 顺序（与直觉相反）。
4. **D5 真实路径**：入口 = P2 密文域加 Enc(r) → P0 白名单①掩码解密 → y₁ 分发（P1 收 y₁ / P2 持 −r）；出口 = P1 取掩码 s → P2 合成 fresh `Enc(v)=Enc(w)−Enc(s)`；转换数公式 **10n/层**。
5. **S8 申报决策**：管线内转换走**进程内角色直连**——1.6MB/密文在纯 Python GCM 通道上 ~20s/往返不可行；通道承载全程改由玩具参数 e2e 验证，真实 socket 化登记 [I] 项挂账。（申报=在设计文档里如实写明实现与规格的差异及理由。）
6. **`bench_protocol` → `p4_protocol_bench.json`**：协议族（握手/帧/审计）性能实测。
7. **estimator 环境打通**：格估计器（见下）的安装 6 条路线全拒后接通 **WSL**（Windows Subsystem for Linux，Windows 内置的 Linux 子系统）+ **micromamba**（轻量包管理器）+ **conda-forge**（社区软件源）安装 **SageMath**（开源数学软件系统）——挂载在 `/opt/sageenv` + 持久仓库 `/opt/le`。**环境纪律：WSL 的 /tmp 目录跨重启易失（systemd 清理），持久产物必须放 /opt**，这条救了后面多次重跑。

**estimator 是什么**：**lattice-estimator**（malb 维护的格密码攻击代价估计器）——输入 LWE 参数，输出攻击代价。**LWE**（Learning With Errors，带误差学习问题）是 CKKS 安全性的数学难题基础；**security_bits=113** 表示在参数 n=2048（环维度）、q=2^60（模数位宽）的 smoke（烟雾测试=小参数快速验证）配置下估算出 113 位安全强度。

**出口**：评审一次通过（无退回）。

**具体实现**：

## 六、一次推理的完整时序

会话建立（证书交换+SM2 挑战响应 → SM2DH 会话密钥 → SM4-GCM 帧+ratchet）之后：

1. P0：分词 → 嵌入 → 定点化 Q16 → CKKS 加密（明文至此不再出 P0）；
2. P0→P2：INFER_REQUEST（密文嵌入向量，走 GCM 通道）；
3. **循环 ×12 层（每层域转换 10n 次）**：
   a. P2：CKKS 线性层（QKV/FFN，对角线+BSGS）；
   b. P2：转换入口，密文域加 Enc(r)；
   c. P0：白名单①掩码解密 x+r → y₁；
   d. P0→P1/P2：y₁ 分发（P2 持 −r）；
   e. P1：MPC 非线性（GELU/Softmax，Beaver 在线乘法）；
   f. P1→P2：RECRYPT → fresh Enc(v) → 残差+LayerNorm → 下一层；
4. P2→P0：INFER_RESULT（logits 密文）；
5. P0：白名单②最终解密 → 标签；
6. 全程：SM3 审计链 append-only；会话结束密钥覆写销毁。

信息流审计视角：P0 见明文但白名单受限；P1/P2 见密文与份额；通道观察者只见 GCM 信封。中间状态在任一单方视角下均为均匀随机（t=1 的含义）。

## 九、常见问题（技术向）

**Q：掩码为什么 ≤2^20？**
掩码量级↑⇒编码残差与 ulp 抖动线性放大（实测 2^37 时 δ≤5），且 relabeling 加法在 OTP 大值域下受 float64 的 2^53 精确整数域约束（超过 2^53 的整数在 64 位浮点里无法精确表示）。2^20 是精度墙内留有裕量的工作点。

**Q：GCM 自实现为什么必须外部向量？**
计数器偏移一格的 bug 在自洽往返、篡改检测、GF(2^128) 代数测试下全部通过（错误实现与自己一致）。只有 RFC 8998 附录 A.1 这类标准向量能钉住计数器起点。推广规则：一切密码组合层实现必须锚定外部标准测试向量。

**Q：为什么不用更大的 CKKS 参数 / 模式 A？**
SEAL 对 n≥2^16 一律拒绝（TenSEAL 0.3.14 上限 2^15）。2^16 评审路径参数与格估计器数据已备；全密文/模式 A 需 OpenFHE 级后端（支持门限同态与更大参数）。

**Q：t=2 为什么不可避免？升 t 的路径是什么？**
2 计算方结构下份额之和=中间值，两方联合必然重构——信息论上限。升 t 三路线：①client-aided 3-of-3（P0 入环，掩码三方拆分，周级工程量）；②加计算节点 3-of-4 Shamir 分享（**Shamir 分享**=基于多项式插值的门限秘密分享；注意 Z_{2^k} 是环不是域，环上 Shamir 需扩域/双分享技术）；③门限 CKKS（OpenFHE）。见 `docs/02 §3.3`。

**Q：转换为什么是 10n 次/层？**
QKV/FFN/注意力输出的转换点按结构固定，n 为词元数——结构守恒实测验证（`docs/04`）。

**Q：怎么证明数字不是编的？**
D8 纪律（数字只能由脚本生成）+ 93 条数据字典（每条主张映射到 JSON 字段）+ 四检黑名单（拦截旧数值回流）。写报告书引用任何数字前，先查 `docs/data_dict.json`。
