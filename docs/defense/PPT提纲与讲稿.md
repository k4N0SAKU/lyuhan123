## P1 封面（0:00–0:10）

**要点**：题目/团队/版本 v1.0 ｜ "数据可用不可见——每个数字可复现"
**讲稿**：各位评委好。我们是 A1-22《面向大模型隐私保护的密码方案软件
设计实现》。今天讲六件事：痛点、方案、安全、性能、创新、演示——所有
数字都指向仓库里可回读的 JSON。

## P2 痛点（0:10–0:50）

**要点**：政务/企业场景敏感字段 → 明文进 API 即违法域；传统方案三缺
（无国密/部署重/开销失控）〔出处：00 §1〕
**讲稿**：市民热线的投诉原文里有姓名、证件号；企业工单里有客户数据。
直接进大模型 API 违反个保法与等保；平台隐私承诺不可验证。现成的 MPC/FHE
框架要么没有国密合法性、要么要求 Linux 集群、开销不可预期。我们的目标：
**三方结构下，明文只在 P0 内存，密文跑完全程推理，控制面全链国密，
单机可复现**。

## P3 方案总览与架构（0:50–1:40）

**要点**：P0/P1/P2 拓扑与端口；角色边界（P0 持 CKKS 私钥，P1/P2 零密钥
材料）〔出处：01 §2；data_dict: code_size.code_lines=9,949〕
**讲稿**：三参与方：P0 数据属主本地嵌入加密，P1 密钥服务负责认证中枢、
密钥全生命周期与审计，P2 推理服务做密文计算。**关键边界**：CKKS 私钥
只存在于 P0，且只经白名单门访问；P1/P2 的上下文是结构性 public_only——
解密会直接抛异常。全栈 9,949 行 Python，测试 34 文件。

## P4 密文推理流程（模式 B）（1:40–2:30）

**要点**：密文线性层（对角线+BSGS，768 明文乘/层）+ 分享域非线性（RCR
模拟申报）+ 转换协议 10n；分段刷新定理〔出处：01 §6/§7；glossary〕
**讲稿**：模式 B：QKV/FFN 在密文域做矩阵乘，非线性（GELU、softmax、
层归一化）转成秘密分享域计算，每层 10 次转换——**每次转换都是一次一密**：
P2 加 Enc(r)，P0 解密看到的只有 x+r。出口处 P1 掩码、P2 密文域合成
fresh 密文，深度重置让 12 层只要段内深度 2。诚实申报：非线性数值是
reveal-compute-reshare 模拟口径（S8），门数与通信如实记账。

## P5 国密控制面（2:30–3:10）

**要点**：SM2 双向认证/SM2DH/SM4-GCM(RFC 8998 锚定)/SM3 哈希链审计/
密钥状态机+两遍覆写〔出处：01 §8；data_dict: p4.establish_p50_ms=316ms〕
**讲稿**：认证是 CA 离线根签发的证书 + 挑战应答双向验证，防重放、防反射；
会话密钥经 GB/T 32918.3 SM2DH 协商，通道是自实现的 SM4-GCM——我们用
RFC 8998 标准向量做过逐字节锚定，这一步抓出了计数器偏移的隐蔽 bug。
密钥销毁是登记表逐条两遍覆写+全零核对，审计日志是 SM3 哈希链，改一条
就能定位。握手全程 p50 316 毫秒。

## P6 安全：威胁模型与五类攻击（3:10–4:10）

**要点**：n=3,t=1；五类攻击 30 项判定 28/2/0；t=2 边界演示如实〔出处：
02 §2/§3；03；data_dict: attacks.*〕
**讲稿**：敌手模型：半诚实参与方 + 恶意网络，合谋门限 t=1。五类攻击——
窃听、中间人、结果篡改、重放、合谋——**全部有自动化测试**：30 项判定，
28 项防御成功，0 项失败。剩下 2 项是**我们自己声明的 t=2 失效面演示**：
P1+P2 合谋可以从掩码分享重构输入 token——这是掩码分享构造的固有边界，
不是漏洞；文档 §3.3 提前写明，并给出两条缓解路径（模式 A 或 2-of-3 门限）。
安全论证用半诚实模拟器：P1、P2 的视图逐条给出可模拟构造。

## P7 性能：四项资源指标（4:10–5:00）

**要点**：矩阵 4/8/12 层 P50=121.7/237.7/371.8s；内存 max 15.7GiB；
流量逐通道〔出处：04 §2；data_dict: matrix.*〕
**讲稿**：四项指标全部脚本自动采集、每配置 20 轮 P50/P95：密文推理
4/8/12 层 P50 分别 121.7、237.7、371.8 秒，回环 CPU；内存增量 max
15.7 GiB、最长单轮 33 分钟——我们按 max 口径建议演示机 ≥24GB，
**不按中位数美化**。流量按通道逐帧计数含协议头。与明文基线 23.6ms 的
~15700 倍差距我们直说：瓶颈在 CKKS 矩阵乘与转换往返，优化路径写在
04 §7 与 05 里。

## P8 基线对比五维（5:00–5:40）

**要点**：五维表+数据来源列；SPU 未部署的申报与引用口径；国密边界〔出处：
04 §5/§7〕
**讲稿**：与 SecretFlow/SPU、PUMA、MPCFormer、BumbleBee 的五维对比：
每行都标"实测"还是"文献"。SPU 在本机 Windows 无发行版——我们**申报
未部署**，只引用 PUMA 论文里对 SPU 的实测数据并标注差异。国密合规边界
如实：控制面全链国密，数据面引擎是国际标准 CKKS——纯国密同态依赖国产
生态，是扩展方向，不冒充。

## P9 创新点（5:40–6:30）

**要点**：C2 1.000@−34.1%（含负结果）；C3 row-sum 5.39×〔出处：05 §1/§2；
data_dict: c2.conv_fp16_emb_q22.*, c3.d256.ratio_*〕
**讲稿**：两个创新点都有开/关 A/B。C2 参数自适应：conv_fp16+emb_q22
组合**一致率一点不掉（1.000）**，体积 474.7→312.7 MiB，省 34.1%；更诚实
的是负结果——两个"自动选择器"都失效了，因为贪心解码对权重扰动是混沌
敏感的，逐张量误差阈值没意义，这直接产出了"端到端闸门"的正确设计。
C3：我们自己造了 row-sum 对照实现，实测比现役对角线+BSGS 慢 5.39 倍——
**用实测推翻了自己项目早期的排序推测**。
